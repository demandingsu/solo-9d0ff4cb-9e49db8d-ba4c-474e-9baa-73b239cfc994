# 馆藏成套器物核对工具

供馆藏编目员核查**成套器物目录是否漏录、错挂**的网页工具：
输入藏品列表页地址，工具沿同站分页抓取套件与器件详情，双向核对
「套件列出的器件编号」与「器件标注的所属套件」，并给出带来源链接的核对报告。

技术栈：Python + FastAPI + BeautifulSoup；Docker Compose 一键启动核对工具与本地样本目录站，全程离线可用。

## 快速开始

```bash
docker compose up --build
```

| 服务 | 地址 | 说明 |
| --- | --- | --- |
| 核对工具 | http://localhost:8000 | 输入列表页地址，查看核对报告 |
| 样本目录站 | http://localhost:8001 | 正常目录入口（首页即目录第 1 页） |
| 故障演示一·器件详情 404 | http://localhost:8001/broken-1.html | 仅器件详情失败、套件目录完整 |
| 故障演示二·列表分页 404 | http://localhost:8001/broken-2.html | 分页失效导致套件目录不完整 |
| 故障演示三·套件详情 503 | http://localhost:8001/suite/t007.html | 套件详情服务不可用（从 broken-3 进入） |
| 故障演示四·抓取截断 | http://localhost:8001/broken-4.html | 配合 `max_pages=5` 参数演示截断 |

首页已预填样本站地址，点击「开始核对」即可；全部来源链接均可在浏览器离线打开对照。

## 核对规则（判定口径）

| 类别 | 判定 |
| --- | --- |
| **缺记录** | 套件列出了某器件编号，但完整抓取后目录中不存在该编号的器件详情 |
| **归属不符** | 两份均已成功抓取的页面直接证实的互指不一致（含所属套件在完整目录中不存在、套件未列入该器件、器件未注明所属套件、编号与详情页不符） |
| **未被套件列入** | 器件既未注明所属套件，也没有任何套件将其列入；**仅当套件目录完整时才下此结论** |
| **无法确认（正向）** | 存在抓取失败 / 抓取截断时，未找到的器件编号不直接判为缺记录，单独列出，报告标记「核对不完整」并附失败地址 |
| **无法确认（反向）** | 套件详情或列表分页抓取失败、抓取截断导致套件记录缺失时，依赖这些记录的反向结论（器件未注明套件、器件指向未抓到的套件）不直接判「归属不符 / 未被套件列入」，改判无法确认，并显示信息缺口与失败地址 |
| **跨页重复** | 同一详情页被多个分页重复链接时只抓取一次、只统计一次，报告中列出重复引用情况 |

判定时区分两类抓取失败：

- **仅器件详情页（`/item/`）失败**：不破坏套件目录完整性，已抓取器件的反向结论（一致 / 归属不符 / 未被套件列入）照常判定。
- **套件详情页（`/suite/`）或列表分页失败、抓取截断**：套件目录不完整，凡依赖缺失套件记录的反向结论一律改判「无法确认」。
- 无论存在何种抓取失败，**两份已抓取页面直接证实的错挂**（如套件页清单列入某器件、器件页却标注别的套件）始终照常报告。

`/check` 支持可选参数 `max_pages`（1–400，默认 400），用于限制单次抓取页数、离线复现抓取截断场景。

报告末尾附「套件 → 器件」「器件 → 套件」双向对照明细，便于人工复核。

## 样本数据内置的问题（用于验证工具）

正常目录（`http://localhost:8001/`）：

- `瓷-104`：套件 套-001 列出，但目录中无详情页 → **缺记录**
- `瓷-202`：套件 套-002 列入，器件页却标注属「套-003」（未收录）→ **归属不符**（双向各一条）
- `瓷-203`：器件页标注属 套-002，但 套-002 未将其列入 → **归属不符**
- `瓷-301`：无所属套件，亦无套件列入 → **未被套件列入**
- `瓷-101`：同时出现在目录第 1、2 页 → **跨页重复**，只算一次

残缺目录一（`http://localhost:8001/broken-1.html`，仅器件详情 404）：

- `瓷-901` 详情页 404 → 报告标记**核对不完整**、列出失败地址，该器件记为正向**无法确认**
- `瓷-902` 无详情页，但因存在抓取失败 → 正向**无法确认**，不判缺记录
- `瓷-903` 未注明套件、套-009 清单也未列入：失败的只是器件详情页、套件目录完整 → 照常判**未被套件列入**

残缺目录二（`http://localhost:8001/broken-2.html`，列表分页 404）：

- 第 2 页 `list-2-missing.html` 返回 404，套件目录不完整
- `瓷-503` 未注明所属套件 → 不判「未被套件列入」，改判反向**无法确认**，缺口显示分页失败地址
- `瓷-504` 指向缺失分页中的套-006（链接同样 404）→ 反向**无法确认**，直接相关失败地址为套-006
- `瓷-505`：套-005 清单已列入它、器件页却标注套-006，两份已抓取页面直接证实 → 仍报**归属不符**

残缺目录三（`http://localhost:8001/broken-3.html`，套件详情 503）：

- nginx 对 `/suite/t007.html` 直接返回 **503**（静态文件保留供人工查看）
- `瓷-601` 标注属套-007 → 反向**无法确认**，直接失败地址为返回 503 的套件页
- `瓷-602` 未注明套件 → 反向**无法确认**（缺失的套-007 清单本可能列入它）
- `瓷-604`（套-008 已抓取但未列入）、`瓷-605`（套-008 列入但本页标注套-009）→ 两份已抓取页面证实，仍报**归属不符**

残缺目录四（`http://localhost:8001/broken-4.html?` 经首页链接以 `max_pages=5` 核对，抓取截断）：

- 报告提示「达到抓取页数上限（5），结果可能不完整」，套件目录视为不完整
- 已抓取的 `瓷-704` 未注明套件 → 反向**无法确认**并附截断说明；`瓷-701` 与套-010 双向一致不受影响
- 去掉 `max_pages` 完整抓取后，`瓷-702`、`瓷-704` 恢复为**未被套件列入**，`瓷-703` 恢复为**一致**

## 页面识别约定（接入真实目录站）

- 页面类型：`<meta name="page-kind" content="list|suite|item">`（缺省按列表页处理）
- 分页：列表页中的 `<a rel="next" href="...">`；仅跟随**同站**链接
- 详情链接：路径含 `/suite/` 或 `/item/` 的同站链接
- 套件页：编号 `.suite-no`；器件清单位于 `ul.members li`，编号为 `.acc-no`，`<a>` 为可选详情链接
- 器件页：编号 `.acc-no`；所属套件为 `.field-suite` 内的 `.suite-no`（无此标记视为未注明）

## 容器间地址改写

浏览器访问样本站用 `localhost:8001`，而 app 容器内需通过服务名 `sample-site:80` 抓取。
compose 中为 app 设置了：

```
URL_FETCH_REWRITE=localhost:8001->sample-site:80;127.0.0.1:8001->sample-site:80
```

抓取时按此规则改写主机，**报告中的来源链接仍保留原始地址**，浏览器可直接打开。
本机直接运行（非 Docker）时无需设置该变量。

## 本地开发（不用 Docker）

```bash
pip install -r app/requirements.txt
python3 -m http.server 8001 --directory sample-site/html &   # 样本站
cd app && uvicorn main:app --port 8000                        # 核对工具
```

## 目录结构

```
├── docker-compose.yml      # 一键启动 app + 样本站
├── app/                    # FastAPI 核对工具
│   ├── main.py             # 路由：/ 表单、/check 报告、/healthz
│   ├── crawler.py          # 同站分页抓取（去重、失败记录、地址改写）
│   ├── checker.py          # 双向核对逻辑
│   ├── models.py           # 数据模型
│   └── templates/          # 表单 / 报告 / 错误页
└── sample-site/            # 本地样本目录站（nginx 静态站）
    └── html/               # 列表分页、套件页、器件页（含内置问题数据）
```

## 限制

- 仅抓取与起始地址同站（同协议、主机、端口）的页面；单次最多抓取 400 页（可用 `/check` 的 `max_pages` 参数调小以复现截断），超限会在报告中提示「结果可能不完整」，依赖未抓到套件记录的反向结论改判「无法确认」
- 抓取为同步执行，适合目录级规模；超大目录请分页核对
- 页面结构需符合上述识别约定
